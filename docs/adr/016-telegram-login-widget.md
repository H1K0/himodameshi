## Контекст

Одна из дисциплин, по которым сдаётся проект, требует интеграцию с Telegram. Какой именно она будет — не так важно, но в том или ином виде она должна быть.

Изначально планировался Telegram-бот. Но Bot API (`api.telegram.org`) недоступен с серверов в РФ, а туннеля с домашнего сервера наружу нет. У пользователей Telegram при этом работает — через их собственный VPN на телефоне или компьютере.

Есть и вторая причина посмотреть на Telegram. В Himo Hub решено обойтись без email: регистрация по уникальному нику и паролю, почта не собирается и не отправляется. Значит, восстановить доступ без отдельного механизма можно только сбросом пароля администратором через CLI.

## Решение

Hub поддерживает вход через **Telegram Login Widget** — в веб-интерфейсе.

- Учётная запись по-прежнему создаётся по нику и паролю. Telegram — второй способ входа: пользователь привязывает его в профиле, после этого может входить через виджет, и это же служит способом восстановить доступ при забытом пароле. Регистрации через Telegram без пароля нет.
- Для виджета создаётся бот через BotFather; к нему привязывается домен Hub — `himo.hakoniwa.ru`. Для dev-окружения — отдельный домен и отдельный бот.
- Виджет загружается и работает в браузере пользователя. Сервер получает от виджета данные пользователя (Telegram ID, username, имя) с подписью и проверяет её сам: HMAC-SHA256 по данным, ключ — SHA-256 от токена бота, плюс свежесть `auth_date`. Сервер к Telegram не обращается.
- В мобильном приложении в версии 1 вход только по паролю.

Отправка карточки кабеля из приложения через системное меню «Поделиться» (картинкой или PDF) — отдельная функция приложения, а не интеграция с Telegram: приложение передаёт файл операционной системе, Telegram выбирает пользователь.

## Рассмотренные варианты

- **Бот на сервере** (long polling или webhook) — полноценная интеграция: уведомления команде, карточки кабелей в чате. Невозможен: сервер не достаёт до Bot API.
- **Бот через туннель или сервер за рубежом** — та же функциональность. Но нужна дополнительная инфраструктура и расходы, плюс ещё одна точка отказа и зависимость от зарубежного хостинга.
- **Вызовы Bot API прямо из приложения** через VPN пользователя — обходит блокировку. Но токен бота оказывается внутри приложения, то есть фактически публичным: любой может извлечь его и управлять ботом.
- **Только ссылки `t.me/share`** — веб и приложение открывают Telegram с готовым сообщением. Блокировка не мешает, но это открытие Telegram, а не интеграция с ним.
- **Telegram Mini App** — приложение внутри Telegram. Требует бота, а значит, тот же доступ к Bot API.
- **Login Widget (выбран).**

## Обоснование

Критерии в порядке важности: работоспособность при блокировке Bot API с сервера > реальная, а не формальная связь с Telegram > отсутствие новой инфраструктуры > польза для пользователя.

Login Widget — единственный вариант, где сервер вообще не обращается к Telegram: подпись проверяется локально по токену бота. Блокировка его не касается, туннель не нужен. При этом это настоящий продукт платформы Telegram: бот, привязка домена, подтверждение входа в самом Telegram, данные пользователя от Telegram с криптографической подписью.

Заодно он закрывает пробел, появившийся после отказа от email: второй способ входа и самостоятельное восстановление доступа без администратора.

## Последствия

**Плюсы:**

- Интеграция работает без доступа сервера к Telegram и без новой инфраструктуры.
- Пользователь получает второй способ входа и может восстановить доступ сам.
- Вход по паролю остаётся, поэтому Telegram не обязателен.

**Минусы и ограничения:**

- Интеграция «тонкая»: только вход, бот ничего не пишет. Есть риск, что для дисциплины этого окажется недостаточно — тогда интеграция расширяется отдельной задачей.
- Без VPN `telegram.org` у пользователя может не открыться — тогда виджет не загрузится, и остаётся вход по паролю.
- Виджет работает только на домене, указанном в BotFather: для dev и prod нужны два бота, а локально виджет не проверить без туннеля.
- Токен бота — секрет, хранится только на сервере в переменных окружения.
- При привязке Hub хранит Telegram ID и username. Формулировку о персональных данных в требованиях нужно согласовать с этим.
- В приложении вход через Telegram в версии 1 недоступен.
