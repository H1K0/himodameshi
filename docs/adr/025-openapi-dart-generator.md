## Контекст

Для интеграции мобильного приложения с будущим сервером Hub (API описан в `openapi.yaml`) нам нужен сгенерированный Dart-клиент. Писать HTTP-запросы и классы-модели вручную долго и чревато ошибками при изменении API.

Главная сложность спецификации — насыщенная система ошибок (коды 400, 401, 403, 404, 409, 426 и т.д.). 
Бюджет проекта минимален, а команда не должна тратить время на установку и настройку тяжелых инструментов (например, требующих Java). Необходим генератор, который быстро работает и создает типобезопасный код для обработки всех вариантов ответов сервера.

## Решение

Использовать утилиту `tonik` для генерации пакета `himo_api`. 
Генератор написан на чистом Dart и не требует Java. Сгенерированный клиент на базе `Dio` возвращает результат в виде типа `TonikResult`. Разные HTTP-коды ответов превращаются в отдельные классы (например, `UpdateCableResponse200`, `UpdateCableResponse409`), что позволяет обрабатывать ошибки (`version_conflict`, `cable_archived`) через `switch` без ручного парсинга JSON.

## Рассмотренные варианты

- **openapi_generator** — Dart-обертка над официальным генератором OpenAPI. Плюсы: огромное комьюнити. Не подошел, потому что требует установленной Java (Java 8+) на машинах разработчиков.
- **openapi_flutter_gen** — простой генератор без `build_runner`. Не подошел, потому что неправильно обрабатывает `nullable` поля (например, `note` в объекте `Cable`), что привело бы к падениям приложения при получении `null` от сервера.
- **swagger_parser** — популярный генератор на базе `Retrofit` и `freezed`. Плюсы: обкатан сообществом. Не подошел, потому что не умеет генерировать типизированные ответы на разные коды ошибок, оставляя разработчику ручной разбор исключений.
- **tonik (выбран)**.

## Обоснование

Критерии в порядке важности: типобезопасная обработка ошибок > отсутствие внешних зависимостей (Java) > скорость генерации.

Спецификация Hub API содержит более 10 кодов ошибок. `tonik` — единственный из рассмотренных, кто на уровне языка Dart заставляет разработчика обработать каждый возможный статус-код ответа через `sealed class` / `switch`. Это исключает ситуацию, когда приложение "молча" падает от неизвестной ошибки (например, `409 Conflict`). 

## Последствия

**Плюсы:**

- Сгенерированный клиент надежно защищает от необработанных ошибок сервера.
- Не требует установки Java, генерация происходит за пару секунд.
- В проекте автоматически создаются типобезопасные и предсказуемые обертки для запросов.

**Минусы и ограничения:**

- Генератор молодой и генерирует `allOf` как вложенные классы, что может быть неудобно для некоторых моделей.
- Для работы сгенерированного клиента необходимо добавить в проект зависимость `dio` и `tonik_util`.
