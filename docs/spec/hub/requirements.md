# Требования к Himo Hub

Версия 0.4 · Октябрь 2026

Веб-сервис совместного ведения истории тестирования аудиокабелей. Рабочее название — Himo Hub.

## 1. Назначение и модель

Сервис хранит историю тестирования кабелей централизованно: команда работает с общим парком кабелей, а ведение кабеля можно передать от одного человека другому без потери истории.

Цели:

- **Непрерывная история.** Новый ответственный загружает кабель в своё приложение и продолжает историю; прежние тесты сохраняют авторство.
- **Совместный доступ.** Любой участник команды видит состояние и историю любого кабеля команды — в вебе и в приложении.
- **Контроль деградации.** Любой тест можно сравнить с предыдущим и с эталонным.
- **Сохранность.** Данные не теряются при утере телефона или уходе сотрудника из команды.

Сервис устроен по аналогии с git-хостингом:

| Git-хостинг          | Himo Hub                   | Особенность                                          |
| -------------------- | -------------------------- | ---------------------------------------------------- |
| Организация          | Команда                    | Все участники имеют полный доступ ко всем её кабелям |
| Репозиторий          | Кабель                     | Принадлежит одной команде                            |
| Коммит               | Тест                       | Неизменяем, имеет автора и время измерения           |
| Изменения в коммите  | Результаты измерений       | Со сравнением с предыдущим и эталонным тестом        |
| `git push`           | Выгрузка                   | Без слияний                                          |
| `git clone` / `pull` | Загрузка                   | Инкрементальная, по курсору изменений                |
| `git revert`         | Пометка «недействительный» | Тест остаётся в истории                              |

**Ключевое отличие от git:** история кабеля — линейный журнал без веток. Тест — неизменяемый факт со своим временем, поэтому независимые тесты двух пользователей (в том числе сделанные без связи) не конфликтуют: оба встают в историю по времени измерения. Конфликт возможен только при одновременном изменении атрибутов кабеля — он решается оптимистичной блокировкой (HUB-4).

Сервис общается с мобильным приложением через REST API, с пользователями — через веб-интерфейс. С прибором напрямую не взаимодействует: результаты измерений приходят только через приложение. Недоступность сервиса не мешает тестированию — приложение копит тесты и выгружает их позже.

## 3. Функциональные требования

### HUB-1 Учётные записи

- Регистрация по **нику** и паролю. Ник уникален без учёта регистра; email не запрашивается
- Вход в веб-интерфейс и в мобильное приложение по нику и паролю
- _(Требование дисциплины.)_ Привязка Telegram в профиле и вход через **Telegram Login Widget** — только в веб-интерфейсе ([ADR-016](../../adr/016-telegram-login-widget.md)). Регистрации через Telegram без пароля нет
- Сброс пароля администратором через CLI на сервере — для тех, кто забыл пароль и не привязал Telegram
- Профиль: смена пароля, смена ника (если новый свободен), привязка и отвязка Telegram
- Завершение всех активных сеансов — например, при утере телефона
- Удаление учётной записи: тесты остаются с автором «Удалённый пользователь». Владелец команды с другими участниками сначала передаёт владение

### HUB-2 Команды и участники

- При регистрации создаётся **личное пространство** — команда из одного человека. Приглашать в него нельзя, удалить его нельзя
- Создание команды (название, описание); создатель становится владельцем
- Пользователь может состоять в любом числе команд
- Роли: **владелец** (ровно один) и **участник**, права — в разделе 2
- Приглашение — по ссылке со сроком действия (по умолчанию 7 суток), владелец может её отозвать. Перешедший по ссылке вступает в команду после входа или регистрации
- Владелец может исключить участника, участник может выйти. Владелец выходит только после передачи владения
- При уходе или исключении тесты участника остаются с сохранением авторства, доступ к данным команды (в том числе из приложения) закрывается сразу. Копии на его телефоне не отзываются
- Передача владения другому участнику; прежний владелец становится участником
- Переименование и изменение описания команды
- Удаление команды с подтверждением (ввод названия) — удаляются все её кабели и тесты
- Восстановление удалённой команды в течение 30 суток

### HUB-3 Тарифы

- Тариф — набор ограничений команды. По умолчанию команде назначается бесплатный тариф
- Бесплатный тариф: **не более 5 участников**, включая владельца
- Лимит проверяется при вступлении по приглашению. При превышении — понятный отказ, владелец видит в интерфейсе, что лимит исчерпан
- Значения лимитов задаются конфигурацией, без изменения кода
- Назначение команде другого тарифа администратором

### HUB-4 Кабели

- Кабель принадлежит ровно одной команде
- ID — **UUIDv7**, генерируется приложением при создании кабеля: кабели можно создавать без связи с сервисом
- Атрибуты: имя, тип (`jack_ts`, `jack_trs`, `xlr`), цветная метка, заметка (необязательный свободный текст), ответственный (участник команды или «не назначен»). Служебные: кем и когда создан, когда изменён, версия записи, признак архива
- Тип нельзя изменить после первого теста
- Изменение атрибутов — с версией записи: при расхождении сервер отклоняет изменение как конфликт и возвращает актуальное состояние (оптимистичная блокировка)
- **Ответственный** — информационное поле, на права не влияет. Назначить можно только участника команды; при его уходе поле сбрасывается в «не назначен» с записью в журнал
- **Архив** — кабель скрыт из основного списка и доступен только для чтения: новые тесты и изменения не принимаются. Архивировать и возвращать из архива может любой участник
- **Окончательное удаление** со всей историей — только владелец команды, с подтверждением
- Текущий Health Score кабеля = Health Score последнего действительного теста; если действительных тестов нет — не определён
- Список кабелей: поиск по имени; фильтры по типу, цветной метке, цвету Health Score, ответственному, архиву; сортировка по дате последнего теста, имени, Health Score

### HUB-5 Тесты

- Тест — неизменяемая запись одного сеанса тестирования одного кабеля, от одного до трёх измерений. ID — **UUIDv7**, генерируется приложением в момент тестирования
- Метаданные: автор (кто выгрузил), время измерения (по часам приложения), время приёма сервером, ID прибора, версия протокола `pv`, версия приложения, версия правил расчёта вердиктов и Health Score, версия прошивки (если есть в протоколе)
- Оценки: Health Score с признаком «неполный» ([ADR-011](../../adr/011-health-score-algorithm.md)), необязательная заметка автора
- Результаты — в формате BLE-протокола ([device/ble-protocol.md](../device/ble-protocol.md)):

| Измерение   | Что хранится                                                                                                                                                                         | Типы кабелей      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| Целостность | Сопротивление, Ом, и вердикт (`ok`, `warning`, `open`, `short`) по каждому проводнику + итог. Проводники: `jack_ts` — tip, sleeve; `jack_trs` — tip, ring, sleeve; `xlr` — pin1–pin3 | все               |
| CMRR        | Значение, дБ, и вердикт (`excellent`, `ok`, `fail`)                                                                                                                                  | `jack_trs`, `xlr` |
| АЧХ         | Отклонения, дБ, относительно 1 кГц в точках таблицы частот + вердикт. Таблица частот определяется версией протокола `pv`; сервер выдаёт частоты вместе с отклонениями                | все               |

- Сервер проверяет структуру теста: значения перечислений, соответствие проводников и измерений типу кабеля, диапазоны чисел. Некорректный тест отклоняется целиком с описанием ошибки
- Сервер **не пересчитывает** вердикты и Health Score — хранит рассчитанные приложением вместе с версией правил
- К тесту привязывается ИИ-комментарий к его результатам (HUB-10) — при выгрузке, если комментарий к таким результатам уже получен, или при первом просмотре в вебе. Привязанный комментарий не меняется, в том числе при смене промпта или модели
- Тест нельзя изменить или удалить по отдельности — только вместе с кабелем или командой
- Пометка **«недействительный»** — любым участником, с обязательной причиной; хранится, кто и когда её поставил. Тест остаётся в истории, но не учитывается в Health Score кабеля и не используется как предыдущий или эталонный при сравнении. Пометку можно снять
- История кабеля упорядочена по времени измерения, при совпадении — по ID теста
- Тесты одного кабеля, выполненные разными пользователями независимо (в том числе без связи), не конфликтуют: каждый добавляется в историю

### HUB-6 Просмотр и сравнение

- Страница теста: метаданные, Health Score, ИИ-комментарий, заметка, таблица проводников, значение CMRR, график АЧХ (логарифмическая шкала частот). Если комментарий ещё не привязан, он запрашивается через HUB-10 и подгружается после открытия страницы
- По умолчанию тест сравнивается с **предыдущим** тестом кабеля; доступно сравнение с **эталонным** (первым действительным):

| Измерение    | Сравнение                                       |
| ------------ | ----------------------------------------------- |
| Целостность  | «Было → стало» и разность по каждому проводнику |
| CMRR         | Значения и разность, дБ                         |
| АЧХ          | Наложение кривых и график разности              |
| Health Score | Значения и разность                             |

- Изменение вердикта (ухудшение / улучшение) выделяется цветом и текстом
- Если измерения нет в одном из тестов — «нет данных для сравнения»
- Сравнение с произвольным тестом того же кабеля
- Графики динамики во времени: Health Score, CMRR, сопротивление проводников
- Изменения в пределах погрешности измерений не выделяются как значимые

### HUB-7 Синхронизация с приложением

Протокол синхронизации — [sync.md](sync.md), соглашения API — [ADR-023](../../adr/023-hub-api-conventions.md).

- **Выгрузка:** новые кабели, изменения атрибутов, новые тесты; несколько тестов за одну операцию
- **Идемпотентность:** повторная передача объекта с известным ID не создаёт дубликат, ответ совпадает с ответом на первую передачу. Тот же ID с другим содержимым — отказ как конфликт идентификатора
- Результат — по каждому объекту (принят / отклонён с причиной); ошибка в одном объекте не блокирует остальные
- При первой выгрузке кабеля пользователь выбирает команду (или личное пространство), участником которой он является
- **Каталог** для раздела Hub приложения: кабели команды без результатов (имя, тип, цветная метка, Health Score, дата последнего теста, число тестов, ответственный, архив) — постранично, с поиском и фильтрами из HUB-4
- **Загрузка:** атрибуты кабеля и полная история тестов, постранично
- **Инкрементальная загрузка** по курсору: только изменения после прошлой загрузки — новые тесты, пометки, атрибуты, архив, удаление
- Отказы с понятной причиной: выгрузка в архивный кабель; выгрузка в кабель, которого нет на сервере («кабель не найден» — в том числе удалённый: удаление окончательное, и что кабель был удалён, приложение определяет само, если выгружало его раньше); явный признак «нет доступа к команде» для бывших участников
- Сервер сообщает минимальную поддерживаемую версию приложения; запросы несовместимых версий отклоняются с предложением обновиться
- При загрузке кабеля можно одной операцией назначить себя ответственным

### HUB-8 Веб-интерфейс

- Страницы: регистрация, вход (по паролю и через Telegram); профиль (в том числе привязка Telegram); мои команды; команда (кабели, участники, приглашения, журнал, настройки); кабель; тест
- Страница кабеля: атрибуты, текущий Health Score, лента тестов как список коммитов (дата, автор, прибор, Health Score с признаком неполноты, выполненные измерения, заметка, отметка недействительности)
- Действия: назначение ответственного, архив и возврат, окончательное удаление (владелец), пометка теста и её снятие, управление командой и профилем
- Изменение имени и цветной метки кабеля
- Кабели и тесты создаются **только в приложении** — тест требует прибора
- Постоянные ссылки на кабель и тест для обмена внутри команды
- Экспорт паспорта кабеля в PDF

### HUB-9 Журнал действий

- Фиксирует: вступление, выход и исключение участников; приглашения; передачу владения; создание кабеля, изменение атрибутов и ответственного; архив, возврат и удаление; новые тесты; пометки недействительности
- Запись: время, автор, событие, объект, детали (было / стало)
- Доступен всем участникам, неизменяем, хранится весь срок жизни команды
- Фильтры по типу события, участнику и кабелю; журнал кабеля — на его странице

### HUB-10 ИИ-комментарии

_(Требование дисциплины.)_ Прокси к языковой модели: приложение и веб получают комментарии к результатам тестов через Hub, ключ API модели есть только у сервера. Как устроены комментарии — [architecture.md, раздел 5](../architecture.md#5-ии-комментарии), устройство прокси — [ADR-018](../../adr/018-insights-proxy.md).

- `POST /api/v1/insights`: на входе результаты теста, на выходе комментарий. Учётная запись и токен не нужны — комментарии доступны и тем, кто пользуется только приложением
- Повторный запрос для тех же результатов возвращает тот же комментарий без обращения к модели
- Ключ API модели хранится только на сервере; промпт — в файле `hub/prompts/insight.ru.md`
- Защита ключа: ограничение частоты запросов по IP и общий дневной лимит обращений к модели. Если лимит исчерпан, комментарии временно недоступны, остальные функции работают

## 4. Нефункциональные требования

| Область             | Требования                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Объём и скорость    | ≥ 100 команд, 10 000 кабелей, 1 000 000 тестов без деградации; ≥ 100 одновременных пользователей; чтение ≤ 1 с для 95 % запросов; приём теста ≤ 2 с; не более 100 записей на страницу                                                                                                                                                                                                                                                                          |
| Надёжность          | Доступность ≥ 99 % в месяц без учёта плановых работ (о них предупреждают в вебе); резервное копирование ежедневно, хранение ≥ 14 суток, на отдельном носителе; потеря данных при аварии ≤ 24 ч, восстановление ≤ 8 ч; тест записывается атомарно                                                                                                                                                                                                               |
| Безопасность        | Внешний доступ только по HTTPS (TLS 1.2+), HTTP перенаправляется; TLS завершается на обратном прокси, приложение недоступно извне напрямую; пароли — адаптивный хеш с солью (Argon2id / bcrypt); сеансы — непрозрачные токены, на сервере хранятся только их хеши, отзываются при смене пароля и по запросу ([ADR-022](../../adr/022-hub-authentication.md)); ограничение частоты входа и запросов; журнал событий безопасности; защита от XSS, CSRF, инъекций |
| Изоляция команд     | Членство в команде проверяется при каждом обращении; знание ID объекта не даёт доступа                                                                                                                                                                                                                                                                                                                                                                         |
| Персональные данные | Не запрашиваются: вход по нику, email не собирается. При привязке Telegram хранятся Telegram ID и username; IP-адреса в журналах хранятся ограниченный срок                                                                                                                                                                                                                                                                                                    |
| Интерфейс           | Русский язык, тексты вынесены в ресурсы; адаптивность от 360 px; актуальные Chrome, Firefox, Safari, Edge, Яндекс Браузер; цвета Health Score как в приложении, цвет всегда дублируется числом                                                                                                                                                                                                                                                                 |

## 5. Критерии приёмки

- Выполнены требования с приоритетом Must (приоритеты ведутся в YouGile)
- Типовые сценарии — создание команды, выгрузка и передача кабеля, тесты без связи, ошибочный тест, конфликт атрибутов, уход участника — выполняются без ошибок и потери данных
- Обращение к кабелю или тесту чужой команды по известному ID отклоняется
- Нагрузочная проверка подтверждает показатели раздела 4
- Восстановление из резервной копии выполнено успешно

---

## 6. Вне рамок версии 1

- QR-коды и физические бирки кабелей — глобальную идентификацию обеспечивает UUIDv7
- Публичные ссылки на паспорт кабеля — версия 2
- Перенос кабеля в другую команду, в том числе при продаже с историей — версия 2
- Права на отдельные кабели, дополнительные роли — версия 2
- Оплата и самостоятельная смена тарифа — версия 2
- Email в любом виде: подтверждение адреса, восстановление пароля, уведомления — не входит
- Push-уведомления о событиях команды — версия 2
- Вход через внешних провайдеров (OAuth), кроме Telegram — версия 2
- Telegram-бот — не планируется ([ADR-016](../../adr/016-telegram-login-widget.md))
- Пересчёт вердиктов и Health Score на сервере, ветвление истории, создание тестов в вебе — не планируется
- Фото кабеля — исключено ([ADR-012](../../adr/012-remove-cable-photo.md))
