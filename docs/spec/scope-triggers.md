# Триггеры сокращения и расширения объёма

## Контекст

[Дорожная карта](roadmap.md) описывает план работ и уровни амбиций к 28 мая:

| Уровень      | Что показываем                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------- |
| **Минимум**  | Mock-приложение на телефоне + симуляция в Proteus (хотя бы один тест). Показываются независимо |
| **Цель**     | Реальное устройство собрано + хотя бы один тест на кабеле + приложение подключено по BLE       |
| **Идеально** | Полный MVP по ФТТ: все три теста × все три типа кабелей, BLE, PDF-экспорт, InsightGenerator    |

**Базовая траектория:** команда изначально движется к уровню «Цель». Этот документ описывает два типа отклонений от этой траектории:

- **Б-минус** — прогресс хуже ожидаемого: срезаем объём, но не ниже «Минимума»
- **Б-плюс** — прогресс лучше ожидаемого: поднимаемся выше, вплоть до «Идеально»

Ключевой принцип: решения принимаются **заранее, на определённых датах**, а не в панике или в эйфории за три дня до презентации.

## Б-минус · Триггеры сокращения

### Б-минус 1 — 3 мая · Ревью Этапа 1

#### Ветка А: Proteus не работает

**Критерий проблемы:** в Virtual Terminal Proteus не видны разные значения сопротивления при подстановке разных резисторов — или симуляция вообще не запускается.

**Действия:**

- [ ] Немедленно обратиться к научному руководителю — не откладывать
- [ ] Упростить схему до предела: убрать MCP3208, подавать напряжение от делителя напрямую на ADC ESP32. Цель — показать, что формула и логика верны, а не точность АЦП
- [ ] Если ESP32 в Proteus вызывает трудности — рассмотреть замену на Arduino Uno с тем же алгоритмом
- [ ] Крайний вариант: статическая схема в Proteus + объяснение алгоритма голосом
- [ ] Железо на этом этапе **не заказываем** — симуляция не подтверждена

#### Ветка Б: Приложение не работает

**Критерий проблемы:** приложение не запускается на телефоне или не показывает хотя бы Dashboard с mock-данными.

**Действия:**

- [ ] Убрать Drift — данные хранить в памяти (`List` в Riverpod state). История теряется при перезапуске, но для демо достаточно
- [ ] Сосредоточиться на одном сценарии: один кабель, один тест, один результат с Health Score

---

### Б-минус 2 — 17 мая · Ревью прогресса

#### Ветка А: Железо / прошивка отстают

**Критерий проблемы:** реальное устройство не собрано или тест целостности не даёт стабильных значений на кабеле.

**Действия:**

- [ ] Уровень «Цель» для 28 мая недостижим — принять это явно, не тратить оставшееся время на железо
- [ ] Переключиться на укрепление Proteus-демо: все три теста в симуляции, подготовить 3–4 состояния схемы для быстрого переключения (исправный / обрыв / КЗ)
- [ ] Железо и BLE-интеграция — переносятся на Этап 4 (после 28 мая)

#### Ветка Б: Приложение отстаёт

**Критерий проблемы:** не все 5 экранов готовы, или Health Score не работает, или сохранение в БД сломано.

**Действия:**

- [ ] **InsightGenerator — вычёркиваем**, если не завершён
- [ ] **PDF-экспорт — вычёркиваем**, если не завершён
- [ ] **QR-код — вычёркиваем** в первую очередь, без сожалений
- [ ] Приоритет: стабильность mock-сценария → Health Score с цветовой индикацией → экран «Паспорт» хотя бы с одной сессией

---

### Б-минус 3 — 24 мая · Заморозка фич

**Критерий проблемы:** к дате заморозки что-то нестабильно или не смержено в `dev`.

**Жёсткий приоритет для 28 мая:**

**Must (без этого презентация не состоится):**

- Приложение запускается на телефоне и показывает хотя бы один тест с результатом и Health Score
- Proteus открывается и показывает хотя бы схему (в идеале — работающую симуляцию)

**Should (вылетает только при прямом блокере):**

- Все 5 экранов приложения
- Идентификация кабеля с цветной меткой
- Все три теста в Proteus
- BLE-соединение с прошивкой
- InsightGenerator, PDF-экспорт

**Nice-to-have (вылетает первым, без сожалений):**

- QR-код в PDF
- Анимации и полировка UI
- OLED, индикатор заряда

**Правило:** если Should-фича нестабильна и не чинится за час — отключается для демо, не чинится до последнего момента.

## Б-плюс · Триггеры расширения

### Б-плюс 1 — 3 мая · Зелёный свет на железо

**Критерий:** Proteus показывает тест целостности (разные резисторы → разные значения в Virtual Terminal) И оба направления (приложение + прошивка) идут по плану.

**Действия:**

- [ ] Заказать железо немедленно — в тот же день. Доставка ~7 дней → компоненты ~10 мая
- [ ] Заказать дубли критичных позиций: ESP32-S3 DevKit, AD9833, MCP3208
- [ ] Добавить задачи Ване на приёмку и сборку в Vikunja (неделя 3)
- [ ] Уровень «Цель» к 28 мая становится реалистичным

---

### Б-плюс 2 — 12 мая · Зелёный свет на полный тест-цикл

> Первое BLE-соединение в дорожной карте фиксируется **10 мая** — это техническая точка синхронизации. Два дня до 12 мая отведены на оценку стабильности соединения и приёмку железа, после чего принимается решение о расширении плана.

**Критерий:** железо собрано, первое реальное измерение сопротивления работает, BLE-соединение приложения с заглушкой прошивки установлено.

**Действия:**

- [ ] Добавить в план реализацию CMRR на реальном железе (см. [cmrr-requirements.md](cmrr-requirements.md))
- [ ] Добавить в план реализацию АЧХ на реальном железе (см. [freq-response-requirements.md](freq-response-requirements.md))
- [ ] Параллельно Валера переходит к сохранению результатов в БД и InsightGenerator — эти данные теперь придут от реального устройства
- [ ] Уровень «Идеально» к 28 мая становится возможным при хорошем ходе работ

---

### Б-плюс 3 — 17 мая · Зелёный свет на полный MVP

**Критерий:** все три теста дают стабильные результаты на реальном железе, BLE-интеграция работает без сбоев на двух Android-устройствах (10 циклов подряд без зависаний), приложение сохраняет результаты в БД.

**Действия:**

- [ ] Добавить в план Этапа 3: PDF-экспорт через share sheet с QR-кодом
- [ ] Добавить в план: все три типа кабелей × все три применимых теста
- [ ] Добавить в план: сценарий ошибки (`err_code: 2`) и переподключение BLE
- [ ] Добавить в план: OLED SSD1306 и индикатор заряда батареи (если есть время)
- [ ] Провести полный регрессионный прогон: 10 циклов на 5 кабелях
- [ ] Уровень «Идеально» — полный MVP к 28 мая

## Что НЕ режется ни при каких обстоятельствах

- Приложение запускается на телефоне и показывает хотя бы один тест с результатом
- Health Score окрашен (зелёный / жёлтый / красный)
- Что-то показывается в Proteus — хотя бы схема со словесным объяснением

Если даже это под угрозой — показываем то, что есть. Дата 28 мая фиксирована и не переносится.

---

## Как пользоваться этим документом

1. На каждой дате-триггере команда собирается на короткое ревью (15–30 минут)
2. Проверяется состояние по каждой ветке
3. **Б-минус:** если критерий проблемы выполнен — принять срезание объёма в тот же день, зафиксировать решение в `docs/adr/` как ADR
4. **Б-плюс:** если критерий расширения выполнен — добавить задачи в Vikunja в тот же день, не ждать

После 28 мая этот документ теряет силу. Дальнейшая разработка идёт по дорожной карте Этапа 4 без временны́х ограничений.
