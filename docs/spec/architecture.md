## 1. Общая схема

```
┌─────────────────────────────────────────────────────────────────┐
│         Аппаратный модуль                                       │
│                                                                 │
│  Jack TS/TRS ──┐                                                │
│  XLR M/F    ───┼──► CD74HC4067  ──► ESP32-S3 ──► OLED 128×64    │
│                │    мультиплексор        │        RGB LED       │
│  AD9833 DDS ◄──┘                         │                      │
│  (генератор)                             │ BLE                  │
│  ADS1115 АЦП                             │                      │
│  INA128P усилитель                       ▼                      │
│  TP4056 + 18650                  Мобильное приложение           │
│  USB-C (зарядка + отладка)         Flutter (iOS/Android)        │
└─────────────────────────────────────────────────────────────────┘
```

Устройство проводит измерения автономно, результаты передаются на смартфон по BLE в виде JSON-пакетов. Приложение хранит историю локально и не требует интернета для основных функций.

## 3. Протокол передачи данных

Прошивка передаёт результаты через BLE GATT как JSON-пакет. Одна служба, две характеристики: CMD (app → устройство) и DATA (устройство → app, Notify).

Полная спецификация протокола — в **[docs/spec/ble-protocol.md](ble-protocol.md)**. Изменения в протоколе — через отдельный ADR и смену поля `pv`.

## 4. Программный стек

### 4.1 Мобильное приложение

Архитектура — Clean Architecture с разделением на три слоя: data, domain, presentation.

| Слой / назначение         | Технологии                               |
| ------------------------- | ---------------------------------------- |
| UI-фреймворк              | Flutter (Dart)                           |
| BLE-клиент                | flutter_blue_plus                        |
| Управление состоянием     | Riverpod                                 |
| Локальная БД              | SQLite + drift ORM                       |
| Генерация PDF             | пакет pdf (dart) + системный share sheet |
| QR в PDF-паспорте         | qr_flutter                               |
| Комментарии к результатам | InsightGenerator (rule-based, см. ниже)  |
| Облако (V2)               | Firebase или Supabase                    |

### 4.2 InsightGenerator

Компонент, формирующий комментарии к результатам тестов на естественном языке. Реализован как интерфейс: результат теста на входе, текстовый комментарий на выходе.

В MVP — реализация на правилах и шаблонах с подстановкой значений и вариативными формулировками. Работает офлайн, без задержки. В версии 2 реализацию можно подменить на облачный LLM-слой (Premium-фича) без изменений в UI.

Подробнее — [ADR-006](../adr/006-insight-generator.md).

## 5. Стратегия разработки

Порядок разработки — software-first:

1. **Flutter-приложение с mock-данными** — полноценный UX без реального устройства. Mock-слой изолирует UI от транспорта и подменяется реальным BLE-соединением без изменений в бизнес-логике.
2. **Освоение hardware по модулям** — LED → AD9833 (генератор) → ADS1115 (АЦП) → INA128P (усилитель) → интеграция на макетной плате.
3. **Интеграция** — после валидации UX приложения, под уже зафиксированный JSON-протокол.

Подробнее — [ADR-005](../adr/005-software-first-strategy.md).
