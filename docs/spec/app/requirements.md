## 1. Функциональные требования

### APP-1 Управление тестированием

- Выбор типа кабеля перед тестом: Jack TS, Jack TRS, XLR симметричный
- Запуск любого из трёх тестов по отдельности
- Запуск полного цикла: все три теста последовательно с итоговым отчётом

### APP-2 Измерения и анализ

| Тест        | Что измеряется                                                      | Пороги                                                |
| ----------- | ------------------------------------------------------------------- | ----------------------------------------------------- |
| Целостность | Сопротивление каждого проводника                                    | ОК (<5 Ом) / Предупреждение (5–50 Ом) / Обрыв / КЗ    |
| CMRR        | Коэффициент подавления синфазной помехи, дБ                         | Отлично (>60 дБ) / Удовл. (40–60 дБ) / Плохо (<40 дБ) |
| АЧХ         | Амплитудно-частотная характеристика передачи сигнала 10 Гц – 40 кГц | Отлично / Удовл. / Плохо                              |

Детальные требования к схеме и калибровке CMRR — **[device/cmrr.md](../device/cmrr.md)**.
Детальные требования к схеме, алгоритму и калибровке теста целостности — **[device/continuity.md](../device/continuity.md)**.
Детальные требования к схеме, пиковому детектору и калибровке теста АЧХ — **[device/freq-response.md](../device/freq-response.md)**.

**ИИ-комментарии** _(требование дисциплины)_. К каждому результату приложение показывает комментарий языковой модели на естественном языке ([architecture.md, раздел 5](../architecture.md#5-ии-комментарии)):

- модель объясняет уже рассчитанные приложением вердикты и Health Score, а не оценивает сама;
- комментарий запрашивается через Hub (HUB-10), учётная запись Hub для этого не нужна;
- без связи комментарий появляется, когда связь вернётся; остальные функции от него не зависят.

### APP-3 Отчётность и база данных

- **Health Score** — итоговая оценка состояния кабеля по шкале 0–100. Цвет определяется числовым значением.

  Алгоритм опирается на **численные значения** измерений (сопротивление проводника, CMRR в дБ, отклонение АЧХ в дБ), а не на дискретные статусы. Для балансных кабелей (`xlr`, `jack_trs`) учитываются все три теста; для несимметричного Jack TS — целостность и АЧХ (CMRR не применяется). Обрыв или КЗ хотя бы на одном проводнике → Health Score = 0. Полное описание алгоритма — [health-score.md](health-score.md).

  | Health Score | Цвет    | Трактовка                                        |
  | ------------ | ------- | ------------------------------------------------ |
  | 80–100       | Зелёный | Все пройденные тесты в норме                     |
  | 40–79        | Жёлтый  | Есть отклонения — кабель пригоден, но не идеален |
  | 0–39         | Красный | Критический дефект — требует внимания или замены |

- **Паспорт кабеля** — структурированный отчёт: идентификатор, дата, результаты всех тестов, итоговая оценка
- **Экспорт** — паспорт в PDF (отправка — APP-6)
- **База кабелей** — локальная база с полной историей проверок для каждого кабеля

### APP-4 Идентификация кабелей

- Имя — свободный текст, задаётся при первом тесте
- Цветная метка — выбор из палитры для визуальной идентификации в списке
- Заметка — необязательный свободный текст, можно изменить в паспорте кабеля

### APP-5 Интерфейс приложения

- **Dashboard** — список кабелей с Health Score, статус BLE-соединения с устройством
- **Тестирование** — выбор типа кабеля, пошаговый запуск, прогресс, результаты в реальном времени
- **Паспорт кабеля** — история тестов, динамика параметров, заметка, кнопка «Поделиться»
- **Коллекция** — фильтрация по статусу, поиск по имени и цвету
- **Hub** — вход в Himo Hub, выбор команды, каталог кабелей команды, загрузка кабеля (APP-7)
- **Настройки** — управление устройством, учётная запись Hub

### APP-6 «Поделиться»

- Карточка кабеля — картинкой — и PDF-паспорт отправляются через системное меню «Поделиться» в любое приложение: мессенджер, почту и т. п.

### APP-7 Синхронизация с Himo Hub

Клиентская сторона HUB-7. Синхронизация необязательна: без учётной записи Hub приложение работает полностью.

- Вход по нику и паролю; вход через Telegram в приложении не поддерживается ([ADR-016](../../adr/016-telegram-login-widget.md))
- **Выгрузка** новых кабелей, изменений их атрибутов и новых тестов. При первой выгрузке кабеля пользователь выбирает команду (или личное пространство)
- **Каталог** кабелей команды, **загрузка** кабеля с полной историей, дальше — обновления по курсору изменений
- Без связи тесты копятся и выгружаются, когда связь появится
- Кабели и тесты получают идентификатор **UUIDv7** в момент создания. При обновлении приложения UUIDv7 присваивается уже накопленным кабелям и тестам, чтобы их можно было выгрузить
- Понятные сообщения при отказах Hub: нет доступа к команде, кабель в архиве или удалён, версия приложения устарела

## 2. Нефункциональные требования

| Требование          | Значение                                                          |
| ------------------- | ----------------------------------------------------------------- |
| Платформа           | Android (Flutter)                                                 |
| Хранение данных     | Локально на устройстве пользователя                               |
| Работа без сети     | Тестирование, история и паспорт кабеля не требуют сети            |
| Синхронизация с Hub | Опциональна: без учётной записи Hub приложение работает полностью |

## 3. Вне рамок

- iOS — сборка и поддержка не планируются
- QR-код в PDF-паспорте — до публичных ссылок на паспорт в Hub ([ADR-019](../../adr/019-qr-postponed.md))
- Вход в Hub через Telegram — только в веб-интерфейсе Hub ([ADR-016](../../adr/016-telegram-login-widget.md))
- Фото кабеля — исключено ([ADR-012](../../adr/012-remove-cable-photo.md))
